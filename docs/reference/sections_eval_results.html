Evaluation Results

Evaluation Methodology

Conformance and goal achievement

Protocol conformance (Set A). Let T be a run’s event trace and Mr the projected EFSM for role r. A message event e = (s, r, ℓ, v) conforms iff it is accepted by Ms (structurally legal send) and satisfies any associated refinement predicate ϕℓ(v) from the guard sidecar. The violation rate of a trace is the fraction of events rejected by at least one role’s monitor. Conformance is deterministic, per-message, and requires no LLM judge.

Goal achievement (Set B). Each case defines k goals G1, …, Gk, each anchored to a specific message edge (s, r, ℓ) and a payload predicate ϕi(v). A trial succeeds iff all k goals are satisfied in at least one of its allowed attempts. Goals are graded under two rungs: strict requires exact (s, r, ℓ) match plus ϕi; role-pair requires (s, r) match plus ϕi under any label. Configurations shown the protocol vocabulary are graded strictly; the bare configuration (never shown the labels) is graded on the role-pair rung—a fairness correction adopted after audit (§[sec:fairaudit]).

Design principle. The separation into Set A (structural conformance) and Set B (task completion) is not incidental—it is the empirical instantiation of the theoretical claim that type safety and progress are distinct guarantees. A system can achieve zero violations while failing its goals (the protocol is followed but the session runs out of steps), or achieve all goals while accumulating violations (correct outcome, incorrect path). Reporting both sets is necessary to distinguish safety from liveness.

Consequence-graded violations: the severity scale S0–S4

Each surviving deviation is graded by consequence on five levels: S0 benign (reordering of independent messages; not counted); S1 waste (duplicate message, costs tokens, breaks nothing); S2 broken obligation (skipped read or wrong ordering); S3 non-termination (session exhausts its budget); S4 unauthorized irreversible act (filing before approval). The grading is computed against the partial order of data and authority dependencies declared in the protocol. Empirical validation: across all configurations and runs, every attempt containing an S2+ violation went on to fail its goal.

Experimental configurations

Each experiment runs the same task under five configurations (arms), forming a ladder of increasing protocol enforcement. All share the same intent, role descriptions, model, and retry budget; only the protocol information and enforcement mechanism differ.

The ladder isolates three orthogonal effects: (i) protocol knowledge (bare→min_llmvalid): does telling the agent the protocol help? (ii) enforcement (min_llmvalid→gate): does blocking wrong messages help beyond telling? (iii) scheduling (gate→sched): does polling only enabled roles help beyond blocking? The MAF arm tests an alternative delivery mechanism (global text + LLM-based speaker selection) that represents the dominant industry pattern.

Statistical methodology

All confidence intervals are Wilson score intervals (95%, z = 1.96), appropriate for binomial proportions and well-behaved at boundary values (0% and 100%). Token counts are the primary efficiency metric; wall-clock times are reported but labeled indicative due to parallel execution and rate-limit contention. Each case uses balanced branch allocation (equal trials per protocol branch) to prevent branch-composition confounds.

Experiments and Results

We evaluate on two multi-agent coordination tasks spanning different protocol complexities, each run under two model capability tiers. The design produces a 2 × 2 × 5 matrix: 2 cases × 2 models × 5 arms, with n ≥ 26 per cell on the primary case.

Cases

Finance (6 roles, branching choice, 6 goals). A quarterly revenue report produced by Fetcher, RevenueAnalyst, ExpenseAnalyst, Writer, TaxVerifier, and TaxSpecialist. Revenue above $50k triggers an audit branch requiring TaxSpecialist analysis and TaxVerifier approval before the report can be written. The protocol exercises fan-out notifications, value-dependent branching, and convergence of parallel analysis streams.

AgenticPay Settlement (4 roles, linear, 4 goals). An escrow-mediated trade between Buyer, Seller, Escrow, and Carrier. The protocol is linear (no branching) but requires strict sequencing: deposit → ship → release → settle. A circular-wait variant (each role waits for the other) demonstrates the deadlock the session type prevents.

Models

GPT-5.4 Mini: a cost-efficient model where enforcement effects are most visible (weaker models make more coordination errors). GPT-5.4: a frontier-capability model that tests whether enforcement remains necessary as model quality improves. Both are deployed on Azure AI Foundry.

Five findings emerge from Table 2.

(1) SCHED is model-invariant. The EFSM-scheduled arm achieves 100% goal completion on both models at near-identical cost (∼12.7k tokens/trial, 9.5 calls/trial). No other arm achieves this: every alternative’s success rate is a function of model capability. SCHED’s calls/trial (11 high branch, 8 standard) matches the protocol’s theoretical minimum message count, confirming the scheduler polls only roles with enabled SEND transitions.

(2) Knowledge-only regresses on the stronger model. min_llmvalid drops from 90% (Mini) to 50% (Full)—a 40-percentage-point regression (p < 0.01, Fisher exact). The mechanism: GPT-5.4 produces zero protocol violations (agents follow message ordering correctly) but its verbose outputs consume more turns before reaching the terminal goal (G6 = 50%). This demonstrates that type safety (conformance) and progress (task completion) are orthogonal guarantees: the protocol is followed, but the session runs out of steps. Token cost rises 75% (50, 200 → 87, 613), confirming verbosity as the mechanism.

(3) Gate and MAF scale positively with model capability. gate: 52% → 100% (+48pp). maf: 6.7% → 100% (+93pp). The stronger model’s improved instruction-following makes enforcement unnecessary for correctness—but not for cost (Finding 4).

(4) SCHED is 4.6–6.9× cheaper than every alternative at 100%. Even when all enforced arms succeed, cost differs dramatically: sched at 12.7k tokens vs. maf at 25.1k (2.0×), gate at 37.9k (3.0×), bare at 58.0k (4.6×), min_llmvalid at 87.6k (6.9×). The mechanism is call count: sched makes 9.5 calls/trial (protocol minimum) vs. gate’s 34.0 (round-robin polling of all 6 roles even when 5 are blocked).

(5) The enforcement gradient is non-monotonic across models. On Mini: bare(42%) < maf(7%) < gate(52%) < min_llmvalid(90%) < sched(100%). On Full: bare(0%) < min_llmvalid(50%) < {maf, gate, sched}(100%). Knowledge-only inverts position between models; bare itself regresses (42% → 0% role-pair); only SCHED is monotonically at the top.

The regression mechanism is visible in Table 3. min_llmvalid achieves perfect structural conformance (zero violations) but fails G6 (final report) in 50% of trials. Trace analysis reveals the pattern: without scheduling, the runtime polls all 6 roles every round via round-robin; GPT-5.4’s longer outputs (each valid, each protocol-conforming) consume the step budget before Writer produces the terminal GenerateReport message. On Mini, terser outputs complete within budget (90%); on Full, verbosity exhausts it. This is not a model defect but a structural limitation of observation-only enforcement: a monitor can verify that every message is correct, but it cannot force progress. The scheduler resolves this by eliminating idle polls entirely (9.5 calls vs. 79.0), leaving ample budget for the terminal goal.

On the simpler linear protocol, GPT-5.4 achieves 100% across all protocol-aware arms (Table 4)—confirming that a four-role linear sequence is within a frontier model’s coordination capacity even without enforcement. The differentiation appears on Mini, where the gradient separates: bare (0%) < maf (0% strict, 100% role-pair) < min_llmvalid (55.6%) < gate/sched (100%). Deadlock demonstration. A circular-wait variant of the protocol (unchecked_skills: skill-based agents without shared protocol) produces zero events across all trials—agents wait indefinitely for messages that never arrive. The Scribble checker rejects the circular-wait global type before any agent runs, at zero token cost.

Table 5 reveals a striking non-monotonicity. Most arms improve with model capability (gate: +48pp, maf: +93pp), consistent with the intuition that stronger models need less enforcement. But min_llmvalid regresses (−40pp, p < 0.01)—the capability-without-efficiency trap—and even bare regresses (42% → 0% role-pair) as the stronger model’s assertiveness breaks the accidental serialization that rescued the weaker one. The explanation is that a stronger model with no enforcement produces longer, more detailed outputs that are individually correct (zero violations) but collectively exhaust the session budget. This result falsifies the hypothesis that enforcement becomes unnecessary as models scale, and establishes that SCHED—the only arm combining type safety (gate) with progress (scheduling)—is the only configuration providing model-independent guarantees.

Three regimes of model scaling:

  1. Enforcement-independent (SCHED): 100%/100%, constant cost. The guarantee is structural and does not depend on model quality.

  2. Positively scaling (gate, maf): improve with capability but require the frontier model. Unsuitable for deployments where model quality cannot be guaranteed.

  3. Negatively scaling (min_llmvalid): degrades with capability. Knowledge alone is a trap: the model follows the protocol perfectly while exhausting the budget.

Two mechanisms produce the cost differences (Table 6). Call reduction: SCHED makes 9.5 calls/trial (the protocol’s minimum: 11 messages on the high branch, 8 on standard, averaged) vs. gate’s 34.0 (round-robin polls all 6 roles every round) and bare’s 45.2 (retries on failure inflate the count). Tokens-per-call is roughly constant across arms (∼1.1–1.8k), so the entire cost difference comes from making fewer calls, not shorter ones. Budget exhaustion: min_llmvalid’s 79 calls (vs. 9.5) are all valid—each produces a conforming message—but most are wasted on roles that cannot advance the protocol, consuming budget that would otherwise reach G6.

The per-branch breakdown confirms optimality: sched uses 11.0 calls on high (protocol has 11 messages) and 8.0 on standard (protocol has 8). gate uses 40.0 and 28.0 respectively—the difference is pure idle polling overhead.

Table 7 shows the scheduling dividend grows with protocol complexity. On the linear 4-role protocol, both gate and sched achieve 100% (the linear structure has no out-of-turn ambiguity), but sched saves 55% on tokens by eliminating idle polls. On the 6-role branching protocol, gate degrades to 52% (round-robin polling exhausts retry budget on roles blocked by the branch) while sched maintains 100% and saves 91%. The mechanism is clear: with more roles, round-robin polling wastes proportionally more calls on blocked roles; the EFSM scheduler scales near-optimally because it polls only the (at most 2) enabled roles at each state.

Discussion: implications for multi-agent system design

The results support three design principles:

Principle 1: Type safety does not imply progress. min_llmvalid on GPT-5.4 demonstrates this formally: zero protocol violations, 50% goal completion. A session type guarantees that every message that happens is correct; it does not guarantee that the right messages happen in time. Progress requires a scheduler that restricts polling to enabled roles, preventing budget waste on idle ones.

Principle 2: Model scaling is not a substitute for structural enforcement. The non-monotonic regression of min_llmvalid (90%→50%) shows that “just use a bigger model” can make coordination worse when the system lacks enforcement. A stronger model that is more verbose, more confident, and produces longer outputs will exhaust finite resources faster when nothing constrains it.

Principle 3: The cheapest correct system is the most constrained. SCHED’s 78–91% cost savings come not from compressing outputs but from not making calls whose answers cannot advance the protocol. The protocol itself is the scheduling oracle: the EFSM’s enabled-set at each state is exactly the set of roles worth polling.
